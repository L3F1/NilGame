Experimental H3 GPU probe

This page draws the saved fixture levels/fixtures/connected-h3-cpu.nil.json with the runtime connected shader (engine/geometry/connected-shader.js) through WebGL2, reads the status/distance/normal packets back with gl.readPixels, and compares every pixel with traceRegionSight on the same camera. Nothing is emulated in JavaScript: with no GPU there are no numbers.

Cameras are deliberately non-axis-aligned. Views cover a single H3 ball, E3→H3 and H3→E3 legs, the return leg, a nearer solid against a remote gate at the range limit, a start inside the ball, and the chart boundary. Magenta is numerical/traversal uncertainty; dark checkers are the end of the supported chart — neither is sky. Agreement with the CPU is evidence, not mathematical proof.

Four columns below decide the lead review's four findings:

  • ambientStretch — how far an ambient normalize would be from the metric one at this pose. A view near 1.000 cannot test finding 1 at all; h3-metric-camera-radial is about 1.32.
  • hitShortfall — CPU hits minus GPU hits. An entry-only ball solver (finding 2) makes this large on h3-entry-exit-sweep and h3-beyond-ball, whose ranges are many times the exit root.
  • normal disagreements — compared in the tangent metric through the bounded local-frame encoding, and the decoded vector must itself be metric-unit (finding 3). Clipped RGBA8 ambient normals fail both.
  • answeredRefusals — GPU answers where the CPU refused. This is the exact shape of the rejected aperture relaxation (finding 4); over two thousand refused pixels are checked at 49×37.
